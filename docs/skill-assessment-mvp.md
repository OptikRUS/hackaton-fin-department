# MVP оценки навыков

Игровой Android-клиент остаётся источником фактов и наблюдений по эпизодам.
Backend преобразует принятые наблюдения в итоговые статусы для текущего
профиля и прохождения. Политика `skills-mvp-v1` — простая демонстрационная
логика продукта; её пороги не являются валидированной методикой оценки.

## Когда происходит расчёт

- `POST /v1/profiles/analytics` проверяет и сохраняет пакет, рассчитывает все
  12 FIN-навыков и сохраняет результат в той же транзакции PostgreSQL.
- `POST /v1/profiles/skills/query` возвращает все 12 записей с `policyVersion`
  и `basedOnHistorySequence`. Он также пересчитывает ранее принятые данные:
  после обновления backend повторная отправка истории не нужна.
- Пустой принятый набор даёт `200` и `NO_DATA` для каждого навыка. Если нет
  ни принятой аналитики, ни ранее сохранённой оценки, остаётся
  `409 ASSESSMENT_NOT_READY`.
- Идемпотентный повтор старого batch возвращает его прежнюю квитанцию и не
  откатывает оценку. Данные разных профилей и прохождений не смешиваются.

Форматы запросов и ответов Android не меняются. Поддерживаются существующие
`schemaVersion=1`, `projectionVersion=4`, `evaluatorVersion=1`. Используется
существующая таблица `skill_assessments`. Миграция `0008` добавляет внутренний
номер редакции проекции аналитики, сохраняя существующие данные. Она применяется
стандартным init-контейнером при развёртывании. Обратная миграция отказывается
удалять редакции, если старый ключ не может представить сохранённые данные.

## Правила `skills-mvp-v1`

Учитывается одно наблюдение на пару `(skill, episodeId)` в одном прохождении.
Наблюдение должно иметь ссылки на факты, `completion=COMPLETE`,
`eligibility=ELIGIBLE` и результат `SUPPORTED`, `DIFFICULTY` или `NEUTRAL`.
Незавершённые, неподходящие эпизоды и `INSUFFICIENT_DATA` не дают оценку.
Переданные счётчики проверяются при приёме, но не суммируются между пакетами.

| Условие | Статус |
| --- | --- |
| Нет подходящих завершённых наблюдений | `NO_DATA` |
| Не менее двух `SUPPORTED` без игровой помощи, всего успехов больше трудностей | `MASTERED` |
| Не менее двух `DIFFICULTY`, трудностей больше успехов | `HAS_PROBLEM` |
| Остальные случаи с подходящими данными, включая равенство успехов и трудностей | `PRACTICING` |

«Без игровой помощи» означает пустой `assistance` либо только
`INFORMATION_ONLY`. `HINT`, `WORKED_EXAMPLE`, `ANSWER_REVEALED` и
`ADULT_REPORTED` исключают успех из этого порога, но он остаётся успехом
при сравнении общего числа успехов с трудностями. `adultHelpKnown=false`
не доказывает, что взрослый не помогал. Нейтральные эпизоды показывают
практику, но не добавляют успехов или трудностей.

Примеры: один успех → `PRACTICING`; два успеха без подсказок → `MASTERED`;
две трудности и один успех → `HAS_PROBLEM`; два успеха только с подсказками
→ `PRACTICING`; два успеха и две трудности → `PRACTICING`.

## Пересекающиеся пакеты и восстановление мира

Сохранённые проекции накладываются по возрастанию `throughHistorySequence`,
при равной конечной границе — в порядке принятых редакций. Для старых строк
без известного порядка приёма применяется порядок начала диапазона. Новая
проекция заменяет оценку своего диапазона, включая исчезнувшие наблюдения;
при `historyStartSequence > 0` сохраняются свидетельства из префикса.
Пара эпизод/навык никогда не считается дважды. Промежуточные диапазоны тоже
учитываются: они показывают, когда новое наблюдение заменило старое. Их
исключение могло бы вернуть ранее заменённую оценку из префикса. Исправленный
пакет на тех же границах также сохраняется новой редакцией; прежние
идемпотентные повторы редакцию не создают.

Если эпизод пересекает границу восстановления, его ранее завершённое
наблюдение сохраняется вместо нового неполного. Новое завершённое
наблюдение может его заменить. Backend не восстанавливает весь evaluator
Android по разрозненным половинам истории: это ограничение MVP.

Загрузка и пересчёт запроса сериализуются блокировкой строки аналитики
профиля/прохождения. Оценка хранит максимальную принятую границу истории,
включая пакеты без новых наблюдений.

## Границы этой доработки

Статусы зависят от доступных игровых эпизодов: некоторые FIN-навыки могут
оставаться `NO_DATA`, если игра ещё не сформировала подходящие наблюдения.
Это вычисленный результат, а не отсутствие работающей ручки.
Пустой каталог родительских материалов не блокирует оценку навыков.
`GET /api/parents/{petId}` показывает сохранённую оценку для run последнего
принятого snapshot; до неё все 12 навыков имеют `NO_DATA`. Встроенная игра
по-прежнему получает оценки через `skills/query`.
